# Supabase (optional) — accounts, cross-device progress sync & audit

The site works fully static without this. Adding Supabase enables three things:

1. **Accounts** — passwordless email "magic link" sign-in (no password handling in this repo).
2. **Progress sync** — level/module/exam/XP state follows the learner across devices.
3. **Audit log** — minimal signed-in events (`module`, `exam`, `mission`, `auth`) for the
   public portfolio and self-audit. **Nothing is collected from anonymous visitors.**

## Setup (15 minutes, one time)
1. supabase.com → free account → **New project** (e.g. `cyber-lab`, region Mumbai).
2. Project Settings → **API** → copy **Project URL** + **anon public** key.
   ⚠️ The anon key is safe to expose (RLS protects everything). **Never** place the
   `service_role` key in this repo or any browser code.
3. SQL Editor → run the block below.
4. Authentication → Providers → Email: keep "Confirm email" ON (magic links).
   Authentication → URL Configuration → Site URL: `https://hemantvasistha.github.io`
   and add redirect `https://hemantvasistha.github.io/cyber-lab/`.
5. Edit the committed `config/supabase.json` placeholder with your real values
   (public anon key only — it is designed to be exposed; RLS is the gatekeeper):

```json
{
  "url": "https://YOUR-PROJECT.supabase.co",
  "anonKey": "YOUR-ANON-KEY"
}
```

6. Deploy + push. The site auto-detects the config; the nav pill becomes a live
   Sign in / Sign out control. Anonymous visitors are never affected.

## SQL to paste in the Supabase SQL Editor
```sql
-- progress: one JSONB snapshot of academy state per user
create table if not exists progress (
  user_id uuid primary key references auth.users(id) on delete cascade,
  payload jsonb not null default '{}'::jsonb,
  updated_at timestamptz not null default now()
);

-- audit: minimal, append-only learning events
create table if not exists audit_log (
  id bigint generated by default as identity primary key,
  user_id uuid not null references auth.users(id) on delete cascade,
  event text not null,
  detail text,
  created_at timestamptz not null default now()
);

alter table progress  enable row level security;
alter table audit_log enable row level security;

-- users may only ever touch their own rows
create policy "own progress select" on progress
  for select using (auth.uid() = user_id);
create policy "own progress upsert" on progress
  for insert with check (auth.uid() = user_id);
create policy "own progress update" on progress
  for update using (auth.uid() = user_id);
create policy "own progress delete" on progress
  for delete using (auth.uid() = user_id); -- enables self-service erasure (DPDP)

create policy "own audit insert" on audit_log
  for insert with check (auth.uid() = user_id);
create policy "own audit select" on audit_log
  for select using (auth.uid() = user_id);

-- latest state wins (ts written by the app into payload)
create or replace function touch_updated_at() returns trigger as $$
begin new.updated_at = now(); return new; end $$ language plpgsql;
create trigger progress_touch before update on progress
  for each row execute function touch_updated_at();
```

## How the client behaves
- `app.js` fetches `config/supabase.json`; if it's absent or still the placeholder
  → static mode, sign-in button shows an explainer modal. No network calls are made.
- On sign-in: remote `progress.payload` is merged over local by each level's `ts`
  (latest-write-wins), then local is re-saved. Every `saveProg()` pushes an upsert.
- Audit events are fire-and-forget; failures never block the UI.
- Sign out clears the local user (progress remains on-device + in cloud).

## Deleting a user's data (DPDP erasure)
Supabase Studio → Authentication → Users → select user → **Delete user**.
The `on delete cascade` foreign keys erase their progress + audit rows instantly.
Public pages stay static and anonymous.
