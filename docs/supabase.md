# Supabase (optional) — live dashboard progress + browser journal

The dashboard works fully static without this. Add Supabase **after publishing**
when you want two upgrades:

1. **Live phase status** — flip a phase to ✅ from anywhere (phone included),
   dashboard updates on next visit. No commit needed.
2. **Browser lab journal** — write journal entries from any device; they're stored
   in the cloud AND visible on your public portfolio.

## Setup (15 minutes, one time)
1. Create a free account at supabase.com → **New project** (any name, e.g. `cyber-lab`).
2. Project Settings → **API** → copy the **Project URL** and the **anon public** key.
   ⚠️ Use ONLY the anon key. Never put the `service_role` key anywhere in this repo.
3. SQL Editor → run the block below (creates tables + Row Level Security).
4. In the repo, create `config/supabase.json`:

```json
{
  "url": "https://YOUR-PROJECT.supabase.co",
  "anonKey": "YOUR-ANON-KEY"
}
```

5. Commit + push. The dashboard auto-detects the config and goes live.

## SQL to paste in the Supabase SQL Editor
```sql
create table if not exists lab_progress (
  phase_title text primary key,
  status text not null default 'pend',
  next text
);
create table if not exists journal (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  entry text not null
);
alter table lab_progress enable row level security;
alter table journal enable row level security;
create policy "public read progress" on lab_progress for select using (true);
create policy "public read journal"  on journal     for select using (true);
create policy "anon insert journal"  on journal     for insert with check (true);
```

## How status rows map to the dashboard
`phase_title` must equal the card title text, e.g.:
`🧰 Software install` → status `done` | `pend` → `next` = the "▸ ..." line.

## Row Level Security — what the policies above mean
- Anyone can READ progress + journal (public portfolio — that's the point).
- Anyone can INSERT journal entries (write-as-you-go from the VM browser).
- Nobody can UPDATE/DELETE through the public key except via the Supabase
  dashboard (where you log in) — keep it that way.
